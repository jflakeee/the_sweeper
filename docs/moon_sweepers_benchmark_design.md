# the_sweeper — Moon Sweepers 벤치마크 및 모바일 게임 설계 v1.0

조사일: 2026-11-05 (한국). 목표: 모바일 웹 출시, 이후 Android 배포.
최근 설계 갱신: 2026-11-08 (한국), 첫 구현 기준 통합·착륙장 배치·작업량 규칙 확정.
상태: 설계 문서와 안내 페이지 공개 완료. 게임 실행판·Android 패키징은 아직 수행하지 않았다.
현재 구현 기준은 19절을 먼저 읽고 항목별 참조 절을 적용한다. 이전 버전의 후보와 현행 규칙을 구분한다.

## 1. 결론과 증거 범위

벤치마크 대상은 DragDrop Games의 Moon Sweepers, Steam AppID 5335510이다. 1983년 Moonsweeper와 구분한다. 공식 설명에서 확인한 핵심은 청소→수집→운반·출하→장비/용량 개선→더 넓은 청소다.[S1]

개발 방향은 '거대한 달을 끝없이 청소'보다 '3~5분 구역을 완주하며 청소 방식이 바뀌는 성장 게임'이다. 원작의 이름·캐릭터·모델·UI·음원은 가져오지 않고 the_sweeper 독자 테마와 자산을 사용한다.

이번 조사에서 공식 상점과 개발 공지, Steam 리뷰 원문 10건, 해당 리뷰의 실질적 답글 5건을 읽었다. 리뷰는 2차 요약 페이지[S3]에서 발견한 사례를 원문으로 확인한 목적 표본이다. 긍정 3·부정 7이라는 표본 구성을 전체 여론 비율로 해석하면 안 된다. 중복 출력된 본문은 한 건으로 계산했다.

영상 6개 후보를 확보했지만 YouTube 본문 접근이 제한되어 연속 재생·프레임·자막·YouTube 댓글은 직접 검증하지 못했다. 따라서 아래 영상표는 시청 완료 분석표가 아닌 검증 대기 목록이다. 영상 시간대, 업그레이드 가격, 도달 시간은 추정해 채우지 않았다. 이 제한으로 '플레이영상 딥리서치 완료' 상태는 아니다.

### 반복 플레이를 만드는 이유 — 설계적 해석

1. 손을 움직이면 표면이 바뀐다. 행동과 결과 사이가 짧고, 진행이 숫자와 지형 양쪽에서 보인다.
2. 용량이 차면 판매하고 다음 장비를 산다. 작은 목표가 다음 목표를 자연스럽게 만든다.
3. 도구가 바뀌면 같은 행동의 처리량이 달라진다. 성장의 체감이 직접적이다.
4. 수동 노동이 자동화로 바뀌며 운영자의 역할이 달라진다.
5. 협동에서는 효율 외에 장난·물리 상호작용이 재미가 된다.[R4]

이 해석은 임상적 중독성이나 인과관계의 입증이 아니다. 원작에 확률형 도박 시스템이 있다는 근거도 이번 조사에서 확인하지 못했다. 아래 확률 시스템은 새 게임의 제안이다.

## 6. 모바일 핵심 설계

가칭 the_sweeper. 오염된 소형 위성의 회수 작업을 맡는 독자 설정. 세로형 2.5D 표현, 실제 로직은 2D 구역 기반. 화면 상단에는 용량·구역 완료율, 하단에는 이동 패드·귀환·장비 버튼을 둔다.

1회 플레이는 3~5분 목표다. 직접 청소→적재→회수 지점 판매→선택 업그레이드→구역 완주→정산/다음 구역 선택으로 끝난다. 다음 구역은 사용자가 눌러 시작한다.

아래 수치는 전부 신규 게임의 초기 튜닝 가설이며 원작 수치가 아니다.

| 시점 목표 | 경험 | 초기 값 |
|---|---|---|
| 0~15초 | 즉시 청소·표면 변화 | 초당 6 먼지, 용량 90 |
| 15~45초 | 첫 판매·첫 업그레이드 | 먼지 1당 1크레딧, 최초 개선 50크레딧 |
| 1~3분 | 도구 분기 | 넓은 브러시 또는 고밀도 흡입 |
| 3~5분 | 첫 구역 완료 | 총 먼지 900, 기본 구역 보상 100 |
| 8~15분 | 첫 운송 자동화 | 드론이 적재 운송 담당 |
| 이후 | 신규 먼지·장비 조합 | 일반·고밀도·자성 먼지 3종부터 |

기본 수집은 90÷6=15초마다 만재한다. 왕복과 판매에 8초라면 유효 처리량은 90÷23≈3.91/초이고, 900 먼지를 처리하는 데 약 230초가 필요하다. 이동·구매가 더해지고 업그레이드는 시간을 줄이므로 실제 3~5분 달성은 플레이테스트로 확인한다.

경제의 기본 병목 식: 장기 처리량 = min(수집량, 운송량, 가공량, 출하량). 한쪽만 강화하면 체감이 사라질 수 있다. UI에 각 단계의 초당 처리량과 가득 참 상태를 보여준다. 체류 용량은 일시적 완충이지 지속 처리량 증가로 표시하지 않는다.

확정 성장 축은 범위·용량·이동·판매/가공이다. 장비 교체 때 이전 투자 일부를 연구 점수로 넘겨 초기 업그레이드를 완전히 낭비로 만들지 않는다. 모든 기능을 초반에 해금하지 않고 1·3·6·10 구역에서 새 역할을 연다.

드론은 기본 먼지를 정리하고 플레이어는 희귀 지층 발굴·경로 선택·시설 배치를 한다. 접속 중 무한 대기를 요구하지 않도록 오프라인 수익은 검증된 마지막 처리율의 30%, 최대 4시간을 초기 가설로 둔다. 시각 변경·중복 청구 대응이 없는 로컬 MVP에서는 경쟁 랭킹과 거래를 제공하지 않는다.

## 7. 확률적 긴장감 설계

중독성 목표를 '완주 만족과 자발적 재방문'으로 측정한다. 도박적인 재미는 불확실한 추가 보상과 선택으로 구현한다. 초기안은 현금 구매·환전·아이템 거래가 없는 플레이 보상만 사용한다.

### A. 지층 보너스 — 고정 성장은 유지

구역마다 1회, 완주 보상과 별도로 10회 발굴 게이지를 채우면 보너스를 연다. 별도의 입장료는 없다.

| 결과 | 확률 | 추가 크레딧 |
|---|---:|---:|
| 일반 광물 | 70% | 20 |
| 고급 광물 | 25% | 50 |
| 희귀 유물 | 5% | 150 |

기대 추가 보상은 0.70×20+0.25×50+0.05×150=34다. 기본 100을 포함한 기대 정산은 134. 희귀 유물이 없어도 다음 구역을 열 수 있다. 초기에는 독립 추첨만 적용하며 천장을 도입한다면 기대값·저장 규칙을 다시 계산한다.

### B. 추가 탐사 — 보너스만 걸기

구역 정산 후 기본 보상은 이미 확정한다. 선택형 '탐사 보너스 100'을 받았을 때 즉시 수령하거나 최대 2회 더 탐사한다. 첫 성공은 65%로 180, 실패는 40. 첫 성공 후 두 번째 성공은 50%로 300, 실패는 60. 실패 또는 2회차 결과에서 종료한다. 기본 재화·장비는 감소하지 않는다.

| 선택 | 조건부 기대값 | 확정 수령과 비교 |
|---|---:|---|
| 즉시 종료 | 100 | 변동 없음 |
| 1회 도전 후 종료 | 0.65×180+0.35×40=131 | 평균 +31, 실패 시 보너스 -60 |
| 1회 성공 후 2회 도전 | 0.50×300+0.50×60=180 | 180 확정 수령과 기대값 동일, 변동성 증가 |
| 처음부터 2회 전략 | 0.35×40+0.65×180=131 | 첫 도전과 평균 동일 |

첫 도전의 기대값이 더 높아 도전이 표준 선택이 될 위험이 있다. 이것이 실험에서 드러나면 첫 성공 보상을 132로 조정할 경우 기대값이 99.8로 즉시 수령 100에 근접한다. 정답처럼 고정하지 말고 즉시 수령률과 결과 만족도를 비교한다.

UI는 '65% / 성공 180 / 실패 40 / 기본 보상 영향 없음'을 버튼 앞에 표시한다. 아슬아슬한 실패 조작, 실제와 다른 확률 연출, 실패 직후 재도전 결제는 넣지 않는다. 결과 애니메이션은 건너뛰기 가능하다.

### C. 장비 강화

필수 성능은 확정 업그레이드로 제공한다. 초기 버전에 파괴·하락 강화는 넣지 않는다. 이후 추가할 확률 옵션 재조합은 플레이로 얻은 토큰만 사용하고, 결과 확인 후 기존 옵션 유지 또는 교체를 선택하도록 설계한다. 옵션별 확률과 중복 처리 규칙이 결정되기 전에는 구현하지 않는다.

### 확률·저장 검증

보상 추첨, 재화 차감, 지급, 완료 플래그를 하나의 저장 단위로 처리한다. 보상 화면 재접속은 같은 결과를 보여준다. 무한 새로고침 재추첨을 막는다. 확률 합계 100%, 0/1 경계, 중복 클릭, 강제 종료 복구를 검사한다. 대규모 추첨에서 평균이 계산값에 수렴하는지도 확인한다.

**Loddlenaut: 깨끗해진 뒤 무언가 생기게 한다.** 우리 게임에서는 구역 완료 후 식생·조명·작은 생물이 돌아오는 장면을 보상으로 둔다. 생물 굶주림이나 접속 의무를 추가하지 않고, 복원 상태를 보존한다. 별도 펫 육성 시스템은 초기 범위에 넣지 않는다.

**A Game About Digging A Hole: 다음 층에 대한 호기심을 만든다.** 바닥 무늬와 금속 신호로 매몰물의 존재를 예고한다. 도구를 개선하면 잔해를 벗겨 새로운 구조물을 발견한다. 지형을 무제한 파는 기술 대신 2~3층 덮개와 발견 오브젝트로 표현하는 것이 초기 웹 버전에 적합하다는 판단이다.

**Digseum: 희귀물이 돈으로만 사라지지 않게 한다.** 청소로 나온 유물을 도감에 남기고 첫 발견마다 짧은 설명과 복원된 그림을 제공한다. 박물관 전체 경영 대신 1화면 전시 진열대부터 검증한다. 경제 보너스는 선택 사항이며 기본 구역 해금은 희귀물 운에 묶지 않는다.

**Outpath: 자동화가 다음 일을 열게 한다.** 드론은 이미 익숙한 일반 먼지 운송을 줄이고 플레이어는 새 지층과 장비 조합에 집중한다. 자동화 후 단순히 같은 화면을 더 오래 기다리게 한다면 실패로 본다. 초기 가공은 원료→제품 한 단계로 제한한다.

**Keep on Mining!: 뽑힌 결과 중 선택하게 한다.** 공식 시스템은 특성 점수로 무작위 3장을 공개하고 하나를 고르며, 특성 단계 상승에 따라 바위 HP도 증가한다. 우리 버전은 장비 선택이 어떤 청소 행동을 바꾸는지 먼저 보여주며, 카드 획득 즉시 적/먼지 체력을 올려 보상을 상쇄하는 방식은 초기안에 쓰지 않는다.

**CloverPit: 확률보다 조합을 연구한다.** 우리 게임은 특정 먼지·장비·수집 순서를 결합하면 보너스가 발동하도록 한다. 슬롯을 청소 화면 옆에 추가하는 방식은 핵심 조작과 분리되므로 보류한다. 당첨 연출의 강도보다 플레이어가 다음 판에 다른 조합을 시험하고 싶은지 확인한다.

### 11.5 검증 순서

1. 같은 구역에서 자동 청소의 범위·색 대비·소리를 조정하여 조작 만족도를 확인한다.
2. 확정 성장만으로 첫 구역 완주가 재미있는지 확인한다.
3. 발견물 도감과 복원 보상을 추가하고 다음 구역 진행 이유를 묻는다.
4. 3장 선택을 추가해 경로·도구 사용 방식이 달라지는지 기록한다.
5. 드론 해금 뒤 직접 조작할 이유가 남는지 확인한다.
6. 그 다음 추가 탐사 확률 보너스를 별도 비교한다.

핵심 관찰 항목은 청소 외 대기 시간, 만재 후 방향 혼란, 모듈 선택 시간, 선택 뒤 행동 변화, 완료 후 자발적 다음 구역 시작이다. 체류 시간 증가만으로 개선을 판정하지 않는다.

## 12. King in the Mountain 추가 벤치마크 — v0.3

### 대상과 확인 범위

대상은 Milo Panta의 King in the Mountain, Steam AppID 4767130이다. King of the Mountain이나 다른 드워프 게임이 아니다. 2026-11-05 확인 당시 Steam은 출시 예정일을 2026-11-06으로 표시하고 정식판 이용자 평가는 없었다. 이는 상점 표시 날짜이며 한국 출시 시각을 확정한 것은 아니다. 예전 검색 결과의 10월 30일과 구분한다.[K1]

공식 Steam·개발자 itch.io·0.90 패치·개발자 Reddit 게시물과 이용자 댓글을 확인했다. 직접 실행·영상 연속 시청은 하지 않았다. 개발 중 데모의 의견을 정식판 결함으로 단정하지 않는다. 개발자 10월 22일 패치에 웹 버전 제거가 명시되어 있어, 과거 HTML5 소개만 보고 현재 브라우저 플레이가 가능하다고 안내하면 안 된다.[K3]

### 기본 시스템

개발자는 이전의 금화 중심 성장에서 자원·아이템 제작 중심 성장으로 개편했다고 설명했다. 자원을 확보하고 기지를 늘린 뒤 장비를 제작해 원정 능력을 개선하는 구조다.[K4]

### 반복 플레이와 위험 선택 — 설계 해석

1. 원정마다 끝이 있어 결과를 비교하기 쉽다.
2. 가까운 자원을 확보할지 먼 목표에 시간을 투자할지 고민하게 한다.
3. 돌아온 자원으로 기지가 변하므로 성장의 흔적이 남는다.

### 모바일 적용안: 선택형 회수 원정

아래 수치는 원작 수치가 아닌 신규 실험안이다. 기존 일반 청소의 시간 제한 없는 방향은 유지한다. 최초 3개 구역에서 조작을 익힌 뒤 별도 회수 원정을 소개한다.

| 항목 | 초기 제안 |
|---|---|
| 원정 시간 | 배터리 180초, 화면 비활성화·일시정지에서는 소모 정지 |
| 사전 정보 | 일반 자원·유물 신호·경로별 예상 소요 시간 |
| 조작 | 직접 이동 유지, 드론에는 우선 회수 지점 1개 지정 |
| 시간 종료 | 획득 완료 자원을 정산하고 귀환, 진행 중 채굴만 미완료 |
| 중도 귀환 | 언제든 가능, 보유 자원 정산 |
| 영구 변화 | 발견 기록·기지 개선 보존 |
| 재입장 | 맵 유지/재생성 여부를 명시; 초기에는 고정 원정 맵 |
| 실패 비용 | 시간과 미회수 기회, 기존 장비·재화 차감 없음 |

시간이 부족해도 이미 얻은 자원이 사라지지 않으므로 '안전한 근거리 회수'와 '먼 유물 접근' 사이 기회비용을 만든다. 더 강한 손실 규칙은 별도 검증 없이 추가하지 않는다.

예: 배터리가 60초 남았을 때 A 경로는 이동·작업 총 35초에 일반 자원 80, B 경로는 총 55초에 유물 신호 해제와 일반 자원 40으로 표시한다. B는 신기록·수집, A는 즉시 성장에 유리하다. 신호를 희귀 유물 확정으로 오인시키지 않고 해당 경로의 실제 보상 규칙을 표시한다. 자동 귀환 설계이므로 별도 귀환 이동 시간을 중복 차감하지 않는다.

### 기지 생산은 세 시설로 제한

원정에서 회수한 금속 조각→정제소에서 합금→정비소에서 장비 개선이라는 한 단계 가공을 제안한다. 창고는 보유량·상한을 표시한다. 초반에는 새로운 생산 재료를 동시에 여러 개 요구하지 않는다.

필수 UI:

- 생산 정지 이유: 재료 부족 / 창고 가득 참 / 담당 드론 없음.
- 구매 불가 이유: 필요 120, 보유 80, 저장 상한 100처럼 숫자로 표시.
- 시설 변경: 철거 전에 환급량 표시, 취소 가능.
- 다음 구역: 자동 진입하지 않고 남은 목표 확인.
- 모바일 선택: 한 번 터치하면 대상 강조, 다시 명령 확정. 인물·시설 겹침은 시설 보기로 해결.

작업자 관리가 청소보다 비중이 커지면 초기에는 공장 전담 인원을 없애고 시설 자체 처리율로 단순화한다. 원정에 인원을 보냈다는 이유로 기지 전체가 멈추는 구조는 첫 버전에 넣지 않는다.

### 채택 순서와 검증

최우선 채택은 사전 목표 표시·명확한 종료·생산 병목 설명이다. 원정 모드는 기본 청소와 모듈 선택이 검증된 다음, 자유 기지 건설과 소비형 원정 장비는 그 이후다. 이번 추가로 초기 MVP에 모든 경영 기능을 넣지는 않는다.

통과 기준: 사용자가 원정 출발 이유와 정산 결과를 설명할 수 있고, 생산 정지 원인을 화면에서 찾을 수 있어야 한다. 다음 원정을 하는 이유가 '같은 대기 반복'인지 '다른 자원·경로·준비 실험'인지 인터뷰한다. 원정 화면 복귀·중단·재실행에서 타이머와 정산이 일치해야 한다.

## 13. 구현 기준 상세 설계 v0.4

이 절은 v0.1~0.3의 후보를 정리한 현재 구현 기준이다. 충돌하면 이 절을 우선한다. 아래 수치는 the_sweeper용 설계값이며 벤치마크 게임의 실제 수치나 플레이테스트 결과가 아니다. 이번 단계는 설계이며 구현·배포 완료를 의미하지 않는다.

### 13.2 첫 10구역 콘텐츠 표

먼지량은 적재 단위, 판매가는 종류와 무관하게 단위당 1크레딧이다. 고밀도·자성 먼지는 처리 방식만 달라진다. 표시 시간은 업그레이드를 적절히 사용한 경우의 목표이며 실측 전이다.

| 구역 | 이름 | 먼지량 | 최초 완주 보상 | 새 경험 | 최초 해금 |
|---|---|---:|---:|---|---|
| 1 | 착륙장 | 900 | 100 | 이동·청소·판매 | 기본 도구, 도감 핵심 유물 A |
| 2 | 화물 통로 | 1,050 | 120 | 용량과 왕복 동선 | 광폭 도구 |
| 3 | 압축 폐기장 | 1,200 | 140 | 고밀도 먼지 | 집중 도구, 모듈, 원정, 유물 B |
| 4 | 물류 정거장 | 1,350 | 160 | 회수소 왕복과 운송 필요성 | 완료 후 드론·기지 시설 |
| 5 | 자성 협곡 | 1,500 | 180 | 자성 군집 경로 | 자성 모듈 후보 편입 |
| 6 | 매몰 관측소 | 1,650 | 200 | 덮개 아래 발견물 | 유물 C |
| 7 | 우회 수로 | 1,800 | 220 | 짧고 좁은 길 vs 넓은 길 | 경로 선택 기록 |

| 9 | 폐쇄 공장 | 2,100 | 260 | 세 먼지 종류 혼합 | 도구 조합 복습 |
| 10 | 복원 중심지 | 2,250 | 300 | 배운 시스템으로 완주 | 유물 D, 초기 캠페인 종료 |

구역 1은 3~5분, 이후는 3~6분을 목표로 한다. 고밀도 비중 때문에 처리 시간이 급증하면 먼지량이나 비중을 줄인다. 캠페인 10구역의 명목 판매 수익은 15,750, 최초 완주 보상은 1,920, 합계 17,670크레딧이다. 모듈·원정 수익은 별도다.

다음 구역은 이전 구역의 완료만 요구한다. 입장료·특정 강화·희귀 아이템을 요구하지 않는다. 모든 먼지는 기본 도구로 처리 가능하게 해 성장 재화를 잘못 써도 진행이 막히지 않게 한다.

일반 구역 완료는 처리 가능한 먼지가 0이고 적재물이 모두 판매되었을 때다. 95%에서 잔여 위치를 표시하고, 99.5% 이상이면 '마무리 회수'를 제공해 잔여 먼지의 수량을 적재·정산에 반영한다. 유물은 이 기능으로 자동 발견되지 않는다. 100%인데 적재물이 남으면 '남은 적재물 판매'를 안내한다.

완료한 구역의 재방문은 복원된 상태로 보여준다. '연습 청소'는 별도 사본에서 제공하며 경제 보상을 지급하지 않는다. 반복 수입은 회수 원정으로 제공해 최초 보상 중복을 막는다.

### 13.3 조작·도구 규칙

가상 패드 이동, 이동 방향 전방 자동 청소가 기본이다. 정지 시 마지막 방향을 유지하며 전방 범위 안 먼지를 계속 청소한다. 우측에는 귀환·도구 버튼을 둔다. 귀환은 안전 경로 자동 이동이며 사용자가 움직이면 즉시 취소한다. 순간 이동은 원정 정산 시에만 사용한다.

좌우 조작 배치를 바꿀 수 있다. 목표 터치 영역은 최소 48 CSS px로 잡고 좁은 화면에서는 메뉴를 접는다. 색 외에 모양·문구로 만재와 먼지 종류를 표시한다. 진동·화면 흔들림은 끌 수 있다.

| 도구 | 일반 먼지 처리율 | 고밀도 처리율 | 자성 처리율 | 상대 폭 | 선택 이유 |
|---|---:|---:|---:|---:|---|
| 기본 회수기 | 6/초 | 3/초 | 4/초 | 1.0 | 균형·초기 사용 |
| 광폭 브러시 | 7/초 | 2/초 | 3/초 | 1.6 | 넓은 일반 먼지 |
| 집중 흡입기 | 5/초 | 6/초 | 5/초 | 0.8 | 단단한 지층·정밀 회수 |

수치는 도구 전체의 최대 처리율이다. 범위 안 타일 수만큼 처리율이 곱해지지 않는다. 여러 타일을 동시에 청소하면 예산을 분배한다. 재화는 정수로 처리하고 내부 작업 진행만 소수로 누적한다.

도구는 해금 시 무료 지급, 장착 도구 변경 무료다. 일시정지된 도구 메뉴에서 변경한다. 먼지 종류별 기대 효과를 함께 표시한다.

### 13.4 영구 성장과 경제

기존 '범위·용량·이동·판매' 4축을 다음 표로 구체화한다. 범위는 도구·모듈로 옮기고 영구 성장에는 처리율을 사용한다. 모든 레벨은 초기값에 대한 배수이며 단계별 복리가 아니다.

| 성장 축 | 초기 | 1단계 비용·효과 | 2단계 비용·효과 | 3단계 비용·효과 |
|---|---|---|---|---|
| 처리율 | ×1.0 | 50 / ×1.2 | 350 / ×1.5 | 1,000 / ×2.0 |
| 적재량 | 90 | 150 / 135 | 450 / 180 | 1,200 / 270 |
| 이동 속도 | ×1.0 | 150 / ×1.1 | 450 / ×1.2 | 1,200 / ×1.3 |
| 드론 운송 | 없음 | 600 / 90단위 수송 | 1,000 / 135단위 | 1,800 / 180단위 |

드론 1단계는 4구역 완료 후, 2단계는 6구역 완료 후, 3단계는 8구역 완료 후 구매 가능하다. 표의 비용 합계는 8,400이다. 캠페인 명목 수입 17,670으로 모든 기본 성장을 구매할 수 있지만 실제 시점·선택에 따른 재미는 플레이 검증이 필요하다.

드론은 적재량 80%에서 플레이어에게 접근해 한 번에 가능한 양을 받아 회수소에 운반한다. 플레이어 적재물이 줄어든 양과 드론 적재물이 늘어난 양은 같아야 한다. 드론이 돌아오기 전에도 직접 판매할 수 있다. 수송량은 드론 최대 용량이며 순간 판매 처리율이 아니다.

초기에는 판매 대기열을 만들지 않는다. 회수소 도착 시 즉시 판매한다. 생산·컨베이어 병목은 초기 구현에서 제외하고 드론 왕복 동선만 관찰한다.

### 13.5 모듈 선택의 명세

3구역부터 입장 시 3개 후보를 제시하고 1개를 선택하거나 '기본 장비로 진행'을 고른다. 후보는 구역 상태에 저장하며 새로고침으로 바뀌지 않는다. 선택 취소는 시작 전까지만 가능하다. 일시중단은 모듈을 유지하고 구역 완료 시 해제한다.

| 모듈 | 효과 | 후보 포함 조건 |
|---|---|---|
| 광폭 헤드 | 폭 +30%, 이동 속도 -10% | 일반 먼지 존재 |
| 압축 분쇄 | 고밀도 처리율 +50%, 일반 처리율 -10% | 고밀도 비중 15% 이상 |
| 귀환 터빈 | 적재 80% 이상에서 이동 +40% | 회수소 왕복 가능 |
| 자성 연결 | 자성 타일 완료 시 인접 자성 타일 최대 2개에 진행도 25%씩 | 연결된 자성 군집 존재 |
| 탐지 렌즈 | 발견물 탐지 거리 +50% | 미발견 유물 존재 |
| 정밀 분류 | 먼지 판매 총액 +10%, 도구 처리율 -10% | 판매 가능한 먼지 존재 |

연쇄 진행으로 완료된 타일은 추가 연쇄를 발동하지 않는다. 판매 보너스는 누적 기본 판매액의 10%를 내림한 값에서 이미 지급한 추가액을 뺀 만큼 지급하여 판매를 쪼개도 결과가 같다.

유효 후보가 3개 미만이면 범용 모듈로 채우고, 그래도 부족하면 실제 개수만 보여준다. 유효 후보 집합에서 중복 없이 균등 추출한다. 모든 경우를 '희귀 확률'로 포장하지 않고 후보가 구역에 따라 달라진다고 안내한다. 재추첨 결제·광고는 없다.

### 13.6 원정·기지 상세 규칙

3구역 완료 후 원정 E1을 개방한다. 시간은 실제 플레이가 진행되는 동안만 180초 감소한다. 메뉴·백그라운드·중단 저장에서는 정지한다. 종료 시 작업이 끝난 자원은 보존하고 진행 중 타일의 부분 작업은 해당 원정 종료와 함께 사라진다.

새 원정은 같은 배치의 새 자원으로 시작한다. 이전 원정을 이어하기는 동일한 잔여 자원·배터리로 재개한다. 도감과 최고 탐사 깊이는 영구 보존한다. 시작 비용과 일일 횟수 제한은 없다.

원정에는 일반 먼지 대신 금속 조각을 배치한다. 먼지 판매와 다른 수입원을 만든다. 채굴 완료 즉시 원정 가방에 담으며 이 가방은 해당 맵의 총 자원을 담을 만큼 충분해 만재 문제가 없다. 귀환 시 조각당 2크레딧으로 매각하거나 보관한다. 최초 E1 총량은 100조각이며 180초 내 수집량은 플레이 검증 대상이다.

4구역 완료 후 창고·정제소·정비소 메뉴를 무료 개방한다. 창고의 금속 조각 상한은 200, 합금 상한은 50이다. 초과 금속 조각은 정산 화면에 매각 예정량을 표시하고 조각당 2크레딧으로 전환한다. 조용히 폐기하지 않는다.

정제는 금속 조각 10→합금 1, 5초의 실제 플레이 시간이다. 한 번에 최대 10개 합금을 예약한다. 재료는 예약 즉시 잠그고 결과를 받을 공간도 확보한다. 취소하면 미완료 분량의 재료를 반환하며 완성분은 유지한다. 화면을 닫아도 활성 플레이 중에는 진행하지만 오프라인에서는 정지한다.

정비소의 초기 레시피는 선택형 1개다: 합금 5+300크레딧→드론 적재 전송 시간 2초에서 1초. 제작은 영구 적용이고 재구매 불가다. 필수 성장 재료가 아니므로 원정을 하지 않아도 캠페인을 끝낼 수 있다.

합금 5에는 조각 50이 필요하므로 매각 기회비용 100+직접 비용 300=400크레딧 상당이다. 이 효과가 체감되지 않으면 가격을 낮추거나 수송 동작을 바꾸며, 제작량만 늘려 시간을 연장하지 않는다.

### 13.7 화면과 상태 전환

| 화면 | 핵심 정보 | 주요 행동 | 복귀 지점 |
|---|---|---|---|
| 거점 | 다음 구역·도감·보유 재화 | 청소/원정/장비 선택 | 마지막 선택 탭 |
| 구역 준비 | 먼지 종류·최초 보상·유물 상태 | 모듈 선택·출발 | 저장된 후보 |
| 일반 청소 | 진행률·적재·회수소 방향 | 이동·귀환·도구 | 같은 위치와 상태 |
| 원정 | 남은 배터리·회수 자원·목표 | 이동·회수·귀환 | 같은 잔여 시간 |
| 정산 | 기본·모듈·최초 보상 구분 | 다음 구역 또는 거점 | 이미 지급된 결과 |
| 기지 | 재료·예약·정지 이유 | 제작·취소 | 기존 생산 상태 |

정산 화면을 닫는 행위로 지급하지 않는다. 정산 데이터 생성과 실제 지급을 함께 저장하고, 화면은 저장된 결과를 보여준다. 앱 종료 후에도 동일 정산을 다시 볼 수 있지만 중복 지급은 없어야 한다.

### 13.8 저장·복구 계약

필수 저장 항목: 저장 형식 버전, 저장 순번, 지갑, 성장 단계, 완료 구역, 도감, 현재 모드, 현재 구역·원정 ID, 잔여 타일 상태, 플레이어·드론 위치와 적재물, 모듈 후보·선택, 원정 남은 시간, 제작 예약, 마지막 정산 ID와 지급 결과.

재화 이동·구매·제작 예약·정산은 하나의 원자적 저장 단위로 처리한다. 저장 성공 전에 완료 연출을 확정하지 않는다. 저장에 실패하면 거래를 확정하지 않고 재시도·저장 내보내기를 제공한다.

활성 플레이의 이동·청소·타이머는 최대 5초마다 체크포인트를 만든다. 중단 이벤트에서도 저장을 시도하지만 강제 종료 시 실행을 보장하지 않으므로, 정상 저장 이후 최대 5초의 현장 진행이 되돌아갈 수 있음을 허용한다. 이때 배터리·먼지·위치·적재물이 같은 시점으로 돌아가야 한다. '진행 손실 0'이라는 기존 목표는 거래 보존과 현장 체크포인트로 구분한다.

이전 정상 저장 1개를 보존한다. 최신 상태가 손상되면 이전 상태로 복구했다는 안내를 표시한다. 여러 탭에서 동시에 재화를 쓰지 않도록 활성 플레이는 한 탭만 허용하고 다른 탭은 읽기 전용으로 둔다. 로컬 저장은 부정행위 방지나 기기 간 동기화를 보장하지 않는다.

| 단계 | 구현 범위 | 통과 기준 |

### 13.10 남은 검증 사항

확정된 것은 구현 규칙의 초안이다. 아직 첫 구역 3~5분 달성, 10구역 전체 분량, 모듈 선택 균형, 저사양 성능, 실제 재방문 효과는 검증되지 않았다. 영상 장면별 분석 미완료도 그대로 남는다. 다음 작업은 기능을 더 늘리는 것보다 A단계 플레이 가능한 구현과 첫 사용자 검증이다.

## 14. 플레이 흐름·레벨 배치·예외 규칙 v0.5

이 절은 v0.4를 보완하며 충돌 항목은 이 절이 우선한다. 새 기능의 수를 늘리기보다 해금 시점과 경제·저장 계약의 모순을 제거한다. 계산 결과는 단순 설계 모델이며 게임 실행 결과가 아니다.

### 14.1 해금 시점 단일 기준

| 시점 | 개방 내용 | 실제 사용 |
|---|---|---|
| 첫 시작 | 기본 회수기, 처리율 1단계 구매 | 1구역 내 첫 판매 후 |
| 1구역 완료 | 적재·이동 1단계 구매, 광폭 도구 무료 | 2구역부터 |
| 2구역 완료 | 집중 도구 무료, 모듈 선택 | 3구역부터 |
| 3구역 완료 | 처리율·적재·이동 2단계 구매, 원정 E1 | 4구역 또는 선택 원정 |
| 4구역 완료 | 드론 1단계 구매, 기지 시설 | 5구역부터 드론 사용 |

13.2의 '해금'은 위 표로 해석한다. 3구역에서 고밀도를 처음 만나기 전에 집중 도구를 제공한다. 4구역은 드론이 필요한 이유를 경험하고 완료 후 구매하는 구역이며, 실제 자동 운송 학습은 5구역이다. 첫 10분 안에 원정까지 모두 소개하려고 서두르지 않는다.

### 14.2 첫 10분 튜토리얼

시간은 안내 목표일 뿐 강제 타이머가 아니다. 사용자가 행동을 완료해야 다음 안내로 진행한다. 안내는 동시에 하나만 보여주고 완료·건너뛰기 상태를 저장한다.

| 목표 시점 | 필요한 행동 | 화면 문구 | 다음 조건 |
|---|---|---|---|
| 0~15초 | 회수기 이동 | “이동하면 앞쪽 먼지를 모아요.” | 먼지 10 수집 |
| 15~40초 | 첫 적재·판매 | “가득 차면 회수소에서 판매하세요.” | 첫 판매 완료 |
| 40~70초 | 첫 강화 | “처리 속도를 높이면 더 빨리 모을 수 있어요.” | 처리율 구매 또는 안내 닫기 |
| 1~3분 | 스스로 청소·귀환 | 필요 시 귀환 버튼 강조 | 진행률 95% |
| 3~5분 | 잔여물 정리·정산 | “남은 먼지는 표시된 곳에 있어요.” | 최초 완주 지급 저장 |
| 5~6분 | 광폭 도구 비교 | “넓게 흩어진 먼지에 유리해요.” | 2구역 출발 |
| 6~10분 | 용량·왕복 차이 체험 | 만재가 반복될 때 적재 개선 안내 | 사용자 속도로 진행 |

만재 상태에서 5초 이상 이동하지 않으면 귀환 안내를 보여주되 자동 귀환시키지 않는다. 잘못된 방향으로 갔다는 이유로 강제 조작하지 않는다. 업그레이드를 건너뛰어도 기본 장비로 진행 가능하다.

### 14.3 구역 배치 규격

초기 지도는 24×32 논리 타일, 플레이어 통로 최소 폭 2타일을 기준으로 제작한다. 화면 전체에 지도를 억지로 축소하지 않고 카메라가 플레이어를 따라간다. 출발점 주변 3×3은 비워 두며, 입장 직후 회수소와 첫 먼지 군집이 함께 보이게 한다.

타일당 먼지량은 고정하지 않고 구역의 총량을 군집별로 분배한다. 서로 다른 먼지 종류를 한 타일에 혼합하지 않는다. 소수 비율에서 생기는 정수 나머지는 일반 먼지 군집에 배분한다.

| 구역 | 일반/고밀도/자성 비율 | 배치 의도 | 주의점 |
|---|---|---|---|
| 1 | 100/0/0 | 회수소 주변 U자형 3군집 | 첫 판매까지 장애물 없음 |
| 2 | 100/0/0 | 좁은 통로와 넓은 적재장 | 광폭 사용 시 길 선택 체감 |
| 3 | 75/25/0 | 고밀도 군집 1곳과 일반 외곽 | 도구 교체를 강제 클릭 퀘스트로 만들지 않음 |
| 4 | 70/30/0 | 회수소에서 서로 다른 거리의 3군집 | 최장 왕복 때문에 대기만 늘어나지 않음 |
| 5 | 70/10/20 | 가까운 일반 군집과 연결 자성 군집 | 드론 첫 사용과 새 먼지 안내를 순서대로 |
| 6 | 60/25/15 | 중앙 유물 덮개와 외곽 순환로 | 유물 미발견이어도 청소 완료 가능 |
| 7 | 70/15/15 | 좁은 지름길과 넓은 우회로 | 두 경로 모두 기본 도구로 접근 가능 |
| 8 | 65/15/20 | 외곽 수집·중앙 회수소 | 드론 2단계 왕복 활용 |
| 9 | 50/25/25 | 종류별 군집이 교대로 배치 | 매 타일 도구 교체를 요구하지 않음 |
| 10 | 45/30/25 | 세 작업 구역과 복원 중심지 | 새로운 시스템 없이 숙련 확인 |

모든 먼지·유물의 접근 가능 여부를 출발점 연결성 검사로 확인한다. 먼지는 이동을 막지 않고 고정 장애물만 경로를 막는다. 드론은 장애물을 통과하는 비행체로 표현해 지상 경로 문제와 분리한다.

맵 완료 시 자동 정리로 접근 불가능한 설계 오류를 숨기지 않는다. 연결성 검사를 통과한 맵에서도 마지막 잔여물 찾기가 피곤한 경우에만 마무리 회수를 사용한다.

### 14.5 보상과 저장의 경계 수정

**원정 정산 선택:** 원정 종료 시 먼저 '정산 대기' 상태로 자원·시간·결과 ID를 저장한다. 보관/매각 수량을 선택한 뒤 한 번의 거래로 지갑·창고·지급 완료 상태를 저장한다. 다시 열면 선택 전 화면 또는 이미 지급된 영수증 중 정확히 하나가 보인다. 이 규칙은 13.7의 즉시 지급 원칙을 원정의 선택형 정산에 맞게 세분화한 것이다.

창고 시설이 없는 3구역 직후에도 원정 자원은 기본 보관함 200까지 보존 가능하다. 4구역 완료는 보관 자체가 아니라 정제·정비 메뉴의 개방이다. 초과량은 수량과 매각액을 표시하고 확정 후 처리한다.

**제작 재료 예약:** 예약된 금속 조각도 창고의 사용 용량에 포함한다. 예를 들어 금속 180에서 100을 예약하면 자유 재료 80+예약 100으로 표시하며 추가 보관 여유는 20이다. 취소는 예약을 자유 재료로 바꾸므로 넘침이 발생하지 않는다. 합금은 보유량+예약 생산량이 50을 넘지 않아야 한다.

**일반 구역 마무리:** 99.5%부터의 마무리 회수는 회수소에서만 실행한다. 잔여 먼지를 별도 회수 서비스로 즉시 판매하여 플레이어·드론 용량을 초과시키지 않는다. 플레이어와 드론의 남은 적재물도 함께 정산하므로 완료 여부가 수송 도중 멈추지 않는다. 잔여 먼지·양쪽 적재물·판매액·최초 보상은 단일 거래로 저장한다.

**유물 회수:** 청소 완료 후 미발견 유물은 복원 구역에 남는다. 재방문해 무료로 회수할 수 있으며 첫 회수 시에만 도감을 갱신한다. 다시 청소하거나 재화를 지불할 필요가 없다.

**드론 인계:** 인계 완료 시점의 플레이어 실제 적재량과 드론 남은 공간 중 작은 값만 이동한다. 그 전에 플레이어가 직접 판매했다면 인계량은 0일 수 있다. 플레이어와 드론 양쪽에서 같은 자원을 판매하지 않는다.

### 14.6 초기 자원 보존 조건

일반 구역에서 '잔여 먼지 + 플레이어 적재 + 드론 적재 + 누적 판매된 기본 먼지량 = 최초 먼지량'이어야 한다. 모듈 판매 보너스와 최초 완주 보상은 먼지량에 포함하지 않는다.

원정은 '미회수 조각 + 현장 보유 조각 + 정산으로 보관/매각한 조각 = 원정 최초 총량'을 확인한다. 원정이 종료된 뒤 버리는 미회수량도 결과 기록에 남긴다.

### 15.3 동일 기대값의 두 단계 선택

실험 프로필은 출발 전에 균형·보전·고변동 중 선택한다. 잠금·희귀도·획득 확률은 없으며 테스트 참여자 모두 사용할 수 있다. 일반 청소의 3장 모듈과 별개다. 원정 도중과 보너스 단계 사이에는 프로필을 바꾸지 못한다.

| 프로필 | 즉시 확보 | 첫 도전 성공 60% | 첫 도전 실패 40% | 두 번째 성공 50% | 두 번째 실패 50% |
|---|---:|---:|---:|---:|---:|
| 균형 | 40 | 60 | 10 | 96 | 24 |
| 보전 | 40 | 56 | 16 | 88 | 24 |
| 고변동 | 40 | 64 | 4 | 112 | 16 |

모든 값은 ‘현재 단계에서 종료할 때 지급하는 총 보너스 크레딧’이다. 성공액을 이전 금액에 더하지 않는다. 첫 도전에 성공해야 두 번째 선택이 생긴다. 실패하면 즉시 종료하고 표의 실패액을 확정한다. 두 번째 결과 후에는 성공·실패 모두 종료한다. 최대 두 번이며 계속 누를 수 없다.

예: 균형에서 40을 확보하거나, 첫 도전으로 60/10을 받는다. 60이 된 경우 그대로 확보하거나 두 번째 도전으로 96/24를 받는다. 40+60+96이 아니다.

산술 검증 결과:

- 균형 첫 도전: 0.6×60+0.4×10=40. 첫 성공 후 두 번째: 0.5×96+0.5×24=60.
- 보전 첫 도전: 0.6×56+0.4×16=40. 첫 성공 후 두 번째: 0.5×88+0.5×24=56.
- 고변동 첫 도전: 0.6×64+0.4×4=40. 첫 성공 후 두 번째: 0.5×112+0.5×16=64.
- 항상 두 번 도전하는 전략의 최종 결과 확률은 첫 실패40%, 두 번째 실패30%, 두 번째 성공30%다. 모든 프로필의 기대 지급액은40이다.

프로필 간 평균 수익 우위는 없다. 보전은 낮은 최고액과 높은 첫 실패액, 고변동은 높은 최고액과 낮은 실패액을 제공한다. 이것이 재미있는 선택인지는 미검증이다. 위험 회피 사용자에게 즉시 확보가 합리적이며, 도전률을 억지로 높이는 것을 목표로 삼지 않는다.

### 15.4 실패 전환의 표현과 제한

실패액은 ‘회수 잔여물’의 정산액으로 표현한다. 화면에는 도전 전 금액, 최종 지급액, 감소액을 함께 쓴다. 예를 들어 균형 첫 실패는 ‘보너스 10 확보 · 선택 전 40에서 30 감소’다. 실제 손실을 성공처럼 축하하거나 숨기지 않는다.

복구를 다음 판 강제 재방문의 조건으로 사용하지 않는다. 연패 수에 따라 확률을 몰래 바꾸지 않는다. 보전 프로필은 처음부터 누구나 선택 가능하므로 특정 유물을 얻어야 손실을 줄일 수 있는 구조가 아니다.

후속 빌드 실험이 필요하면 ‘실패 후 다음 행동에 정보 제공’을 우선 검토한다. 실패할수록 영구 수익이 늘어나는 효과는 반복 실패 파밍과 비교 검증하기 전에는 도입하지 않는다.

### 15.5 모바일 화면 흐름

1. 원정 종료: 회수 금속, 기본 매각 가치, 보너스 자격을 표시한다. 기본 금속은 기존 보관/매각 선택 후 먼저 확정한다.
2. 보너스 선택: 현재 확보 가능액을 가장 크게 표시한다. ‘40 확보’와 ‘추가 탐사’ 버튼을 동등한 크기로 제공한다.
3. 추가 탐사 버튼 옆에 ‘성공60% → 총60 / 실패40% → 총10’을 표시한다. 처음 한 번은 ‘현재40은 추가 지급되지 않음’을 설명한다.
4. 도전 확정 뒤 결과 저장이 성공하면 연출을 재생한다. 결과는 재추첨 없이 건너뛸 수 있다.
5. 첫 성공일 때만 두 번째 선택을 제공한다. 중단·실패·두 번째 결과에서는 최종 영수증과 거점 이동 버튼을 보여준다.

360 CSS px 폭에서도 확률·성공액·실패액을 생략하지 않는다. 두 줄로 나눌 수 있다. 버튼 터치 영역은 기존 48 CSS px 기준을 적용한다. 현재 누르고 있는 손가락을 떼기 전 다음 단계 버튼을 활성화하지 않아 연속 입력으로 두 번 도전하지 않게 한다.

결과에 근접했다는 가짜 룰렛, 시간이 지나면 사라지는 확보 버튼, 실패 직후 재도전 팝업은 사용하지 않는다. 사용자는 앱을 닫고 같은 선택 상태로 돌아올 수 있다.

### 15.6 저장·종료 경계

기존 정산 ID 아래 기본 금속 정산과 보너스 정산을 별도 완료 상태로 기록한다. 기본 금속 정산이 완료되기 전 보너스는 시작할 수 없다. 보너스 대기 중에는 새 원정을 시작하지 못하며, ‘현재 보너스 확보 후 출발’로 한 번에 종료할 수 있다.

보너스에서 보존할 정보는 원정 ID, 규칙 버전, 선택 프로필, 자격 여부, 현재 단계·금액, 확정된 각 도전 결과, 지급 완료 여부다. 프로필별 확률과 보상표는 시작 시점의 버전을 유지한다. 테스트 중 규칙을 바꿔도 진행 중 판은 기존 표로 마무리한다.

도전은 결과와 다음 상태를 먼저 한 번에 저장하고 표시한다. 최초 보너스 상태 생성 시 해당 판의 결과를 고정해 재접속으로 유리한 결과를 다시 뽑지 않게 한다. 최종 금액의 지갑 반영과 지급 완료 상태는 한 번의 거래다. 저장 실패에서는 다음 단계로 넘어가지 않는다. 로컬 저장 편집에 대한 완전한 부정행위 방지를 주장하지 않는다.

구버전 저장은 보너스 없는 기존 원정으로 이어간다. 완료된 과거 원정에 보너스를 소급 지급하지 않는다. 실험 비활성화 시 이미 대기 중인 보너스는 현재 확보 가능액을 중복 없이 지급하고 종료한다.

### 15.7 비교 실험과 채택 기준

첫 비교는 테스트 참여자 단위로 A/B를 배정하고 같은 참여자가 중간에 조건을 바꾸지 않는다. A는 동일 자격에서40 확정 지급, B는 균형 프로필의 선택형 보너스다. 기본 자원·맵·성장 수치는 같게 한다. 세 프로필 비교는 B의 의미가 확인된 다음 진행한다.

측정 항목은 보너스 화면 이해도, 즉시 확보율, 1·2회 도전률, 종료 만족도, 실패 후 이탈, 다음 세션의 자발적 재방문이다. 실제 종료 시간·기본 회수량·분당 수익도 기록해 보너스가 원정 행동을 왜곡하는지 확인한다. 소수 테스트에서 유의한 유지율 개선이나 인과효과를 단정하지 않는다.

초기 사용성 기준은 최소10명이 각자 1회 이상 선택을 완료하고, 최소8명이 ‘기본 금속은 줄지 않음’과 ‘표의 지급액은 누적액이 아님’을 도움 없이 설명하는 것이다. 이는 통계적 출시 성공 기준이 아니라 UI 수정 여부를 결정하는 임시 기준이다. 오입력으로 도전하거나 보상을 잘못 이해한 사례는 평균 점수와 무관하게 원인을 수정한다.

도전률 상승만으로 채택하지 않는다. 이용자가 선택을 이해하면서 기존 원정보다 재미·만족이 나아졌다는 일관된 반응이 있을 때 확대한다. 평균 플레이 시간만 늘고 불만·후회가 커지면 고정 보상으로 되돌린다.

## 16. E1 원정 공간·시간·귀환 설계 v0.7

2026-11-06 한국. 이 절은 E1 프로토타입 제작 규격이다. 180초 제한·기본 자원 보존·선택 정산을 유지한다. 원정의 구체적인 속도·지도·도구 적용과 보너스 자격은 아래 규칙을 우선한다. 수치는 자체 설계와 산술 모델이며 실제 측정값이 아니다.

### 16.1 기다리는 보너스 조건 제거

15.2의 ‘배터리 소진 또는 전량 회수’ 조건은 폐기한다. 최초 E1은 보너스 없이 조작을 익히고, 이후 실험 대상 E1에서 금속50조각 이상을 모으면 조기 귀환·시간 종료·전량 회수 어느 경우든 보너스 자격을 얻는다. 최초 원정의 정상 종료도 귀환 또는 시간 종료로 정의한다. 0조각 귀환도 종료 기록은 남지만 보상은 없다.

50조각 도달 즉시 ‘귀환 시 보너스 선택 가능’을 표시한다. 180초가 끝나기를 기다려도 금액이 더 늘어나지 않는다. 15.3의 확률·보너스 금액·최대2회 규칙은 유지한다. 기본 금속은 1~49조각이어도 모두 보존한다. 보너스 실험이 비활성인 기본판에는 이 자격 안내를 표시하지 않는다.

이 변경으로 50조각 반복 회수가 유리해질 수 있다. 이를 숨기지 않고 아래 경로 계산에서 부분 회수와 완전 회수를 함께 비교한다. 실제로 짧은 반복만 유리해지면 기본 원정의 채굴·이동을 먼저 조정한다. 시간 소진을 다시 보상 조건으로 넣지 않는다.

### 16.2 고정 장비로 첫 실험의 변수 제한

E1 첫 프로토타입은 무료 대여 탐사 장비를 쓴다. 이동2논리 타일/초, 채굴 반경1.25타일, 가방100조각, 도구 전체가 동시에 처리하는 광맥은1개다. 기본 장비로 모든 광맥을 처리할 수 있다. 연타는 필요 없으며 범위 안에서 자동 채굴한다.

캠페인의 처리율·적재·이동 강화, 일반 청소 모듈과 드론은 이 E1 실험에 적용하지 않는다. 출발 화면에 ‘대여 탐사 장비 사용’을 표시한다. 이를 숨겨 성장 효과가 고장 난 것처럼 보이지 않게 한다. 영구 성장과 원정의 연계는 고정 장비에서 경로 재미를 검증한 뒤 별도 설계한다.

이 제한은 E1 프로토타입의 비교 조건이다. 모든 후속 원정을 영구적으로 같은 장비에 묶겠다는 결정은 아니다. 보너스 프로필은 확률 보상에만 영향을 주고 이동·채굴 속도에는 영향을 주지 않는다.

### 16.3 지도 제작 규격

24×32 논리 타일, 좌상단(0,0), 오른쪽+x, 아래+y. 아래 좌표는 이동 경로 중심선의 기준점이다. 통로는 최소2타일 폭이며 격자 스냅 모서리에서 막힘이 없도록 한다.

| 기준점 | 좌표 | 이전 점까지 중심선 거리 | 출발점부터 누적 거리 | 내용 |
|---|---|---:|---:|---|
| S | (4,28) | 0 | 0 | 출발·안내 |
| A | (20,28) | 16 | 16 | 표층 금속20 |

연결은 S→A→B→굴곡점→C다. 첫 E1은 가지 없는 통로로 시작해 채굴 대상을 지나치거나 회수하고 멈추는 선택을 검증한다. 갈림길 탐험이 이미 구현된 것처럼 표현하지 않는다. S와 C는 화면상 가깝지만 벽으로 분리하며, 막힌 구간은 명확하게 보인다. 보이지 않는 벽을 사용하지 않는다.

광맥은 길옆 포켓에 배치하고 이동을 막지 않는다. A나 B를 채굴하지 않고 C로 갈 수 있다. 접근 가능성뿐 아니라 벽을 우회하는 의도치 않은 지름길도 검사한다. 중심선 거리64는 계산 기준이며 넓은 모서리를 대각선으로 통과하면 실제 이동 거리는 짧아질 수 있다. 실제 경로 길이를 측정해 보상 효율을 재계산한다.

### 16.4 채굴과 부분 완료

| 광맥 | 총 조각 | 처리율 | 전체 채굴 시간 | 설명 |

| B 중층 | 30 | 1조각/초 | 30초 | A와 합쳐 보너스 자격50 |

‘깊을수록 단단해서 느리다’는 규칙을 사용하지 않는다. C는 이미 파쇄된 노출 광맥으로 표현한다. 높은 회수 효율은 출발 지도와 광맥 정보에 표시하며 숨겨진 정답으로 두지 않는다.

광맥의 작업량은 조각 단위로 누적한다. 완료된 정수 조각은 즉시 가방에 들어가고, 다음 조각의 소수 진행은 같은 원정에서 광맥을 떠나도 유지한다. 원정 종료 시 미완료 조각의 진행만 사라진다. 예를 들어 C에서 5초 작업하면7조각을 확보하고 다음 조각은50% 진행이다. 가방7조각은 종료해도 보존한다.

여러 광맥이 범위에 들어오면 가장 가까운 광맥 하나를 선택하고 거리 동률은 고정 ID 순서로 처리한다. 이미 채굴 중인 광맥이 유효 범위에 있으면 목표를 유지한다. 타깃이 계속 바뀌는 현상을 막는다.

### 16.6 귀환·시간 종료와 화면

HUD에는 남은 시간, 금속 수량, 귀환 버튼을 표시한다. 보너스 활성판에서만 자격까지 남은 조각 수를 작은 보조 문구로 제공한다. 첫 진입에서는 ‘시간이 끝나도 모은 금속은 보존돼요’를 안내한다.

귀환을 누르면 시뮬레이션과 배터리를 정지하고 ‘금속 N조각을 가지고 종료 / 계속 탐사’ 선택을 보여준다. 종료를 확정하면 현장 자원·부분 진행·가방·종료 사유를 함께 저장하고 정산으로 이동한다. 확인창을 닫으면 같은 상태에서 재개한다. 캠페인의 자동 이동 귀환 버튼과 구분해 원정에서는 ‘탐사 종료’라고 쓴다.

남은30초에 한 번 안내하며 지속 점멸·진동 반복은 하지 않는다. 시간이0이면 해당 시각까지 끝난 조각을 반영하고 종료한다. 전량100조각 회수 시 자동으로 현장 종료하되 새 원정을 자동 시작하지 않는다. 미완료 광맥과 잃은 장비가 있다는 식의 경고는 하지 않는다.

### 16.7 장기 반복의 목표

초기 E1은 금속·선택 정비 제작과 경로 숙련을 제공한다. 최초50조각 회수, 최초100조각 회수, 개인 최단100조각 기록을 도감 기록으로 남긴다. 기록 보상으로 수익 배율·강화 재료를 추가하지 않는다. 기록 갱신은 완전 회수 판끼리만 비교하고 부분 회수 시간과 섞지 않는다.

장비·지도 규칙이 바뀌면 기록에 해당 규칙 버전을 남긴다. 기존 기록은 보존하되 다른 규칙의 기록과 단일 순위를 매기지 않는다. 공개 랭킹은 초기 범위에서 제외한다.

반복이 단조롭다면 보상 배율이나 무한 강화부터 늘리지 않는다. C 접근 방법이 다른 두 번째 지도 한 개를 먼저 검토한다. E1 반복 자체가 불필요하게 느껴지면 캠페인 부가 콘텐츠로 짧게 유지한다.

## 17. 부분 채굴 경제 검증과 첫 플레이 테스트 v0.8

2026-11-06 한국. 이 절은 새 보상 기능을 추가하지 않고 v0.7의 미검증 항목을 구체화한다. 아래 계산은 실행한 산술 분석이고, 사용자 테스트 결과는 아니다.

### 17.1 부분 채굴 조합 검토

A에서0~20, B에서0~30, C에서0~50조각을 회수하는 모든 정수 조합을 열거했다. 전부0인 경우를 제외하면21×31×51−1=33,200개다. 이동은 가장 먼 회수 광맥까지 중심선을 따라 한 번 이동하고, 돌아오는 시간 없이 귀환하는 모델이다.

활성 시간 T는 가장 먼 광맥까지 이동 시간(A8/B18/C32초)에 a+b+c/1.5초를 더한다. 기본 매각액은2(a+b+c), 보너스 활성판의 기대 지급액은 회수량50 이상일 때40이다. 분당 수익은60×총 기대 지급액÷(T+H)이며 H는 준비·정산 시간이다. 모든 조합이180초 이내다.

| 준비·정산 H | 기본 원정의 최고 효율 | 분당 크레딧 | 보너스 활성판의 최고 효율 | 분당 기대 크레딧 |
|---|---|---:|---|---:|
| 0초 | 전량100 | 104.05 | C50만 | 128.57 |
| 4초 | 전량100 | 100.56 | C50만 | 121.15 |
| 8초 | 전량100 | 97.30 | 전량100 | 116.76 |
| 16초 | 전량100 | 91.37 | 전량100 | 109.64 |

C50과 전량100의 효율이 같아지는 H는 약4.67초다. 이 경계보다 빠르게 재시작하는 사용자는 C 반복으로 분당 기대 수익을 높일 수 있다. 두 경우의 활성 시간 차이는50초, 기대 수입 차이는100크레딧이다. 보너스는 이 추가 작업에 붙지 않으므로 빠른 반복을 상대적으로 유리하게 만든다.

50조각 기준의 불연속도 확인했다.49조각은98크레딧,50조각은 기본100+기대 보너스40=140으로, 한 조각을 더 모으면 기대 지급액이42 증가한다. 이는50에서 멈추게 하는 강한 기준점이며, 신규 사용자가 ‘50이 실제 목표’라고 받아들일 수 있다.

계산의 한계: 광맥에 접근하는 동안의 자동 채굴, 모서리 지름길, 광맥 포켓 왕복, 터치 오입력, 생각하는 시간은 제외했다. 회수 대상 조각의 모든 정수 배분을 검토했지만 모든 공간 경로·입력 시퀀스를 검증한 것은 아니다. 기대 수익은 장기 평균이며 개별 확률 결과를 예측하지 않는다.

### 17.2 이번 판정: 기본판 유지, 보너스는 실험 유지

E1 기본판의 금속100·처리율·180초는 변경하지 않는다. 보너스40과50조각 자격은 아직 출시 기준으로 확정하지 않는다. 초기 A/B 테스트에서는 기존 수치를 고정해 행동 변화를 관찰하고, 도중에 수치를 바꾸면 별도 실험 버전으로 구분한다.

1. 첫 구역을 설명 없이 시작하게 하고, 막힘이 발생하면 원인과 도움을 준 시점을 기록한다. 생각을 말하게 하는 진행은 시간을 늘릴 수 있으므로 자연 플레이 시간과 구분한다.

3. 종료 후 ‘시간이 끝나면 무엇이 남나요?’, ‘왜 그 시점에 돌아왔나요?’, ‘다음에는 무엇을 바꾸고 싶나요?’를 묻는다.

10명 전원에게 보너스 A/B의 성과 차이를 입증하려 하지 않는다. 사용성 문제를 고친 다음, 별도의 자발적 플레이 관찰에서 참여자 단위 A/B를 유지한다. 확률 화면을 양쪽 모두 보여주는 연습 세션은 A/B 재방문 분석 대상에서 제외한다.

| 다음 판 시작 | 종료 후 자발적 행동 | 관찰자가 권한 재시도와 구분 |
| 저장·입력 오류 | 발생 상태와 재현 단계 | 재미 점수와 별개로 수정 |

첫 구역은10명 중8명 이상이 도움 없이 완주하는 것을 초기 목표로 삼되, 시간 제한으로 실패 처리하지 않는다. 3~5분은 설계 목표이며, 느린 사용자를 압박하는 판정 기준이 아니다. E1은10명 중8명 이상이 기본 금속 보존과 자유 종료를 설명하면 안내를 잠정 통과시킨다.

중복 지급·자원 소실·버튼 오입력으로 의도하지 않은 도전은 한 건이라도 원인 확인 전 보너스 실험 확대를 중단한다. 참가자가 결과를 싫어한다는 이유만으로 표시 확률을 몰래 바꾸지 않는다. 공정성 이해와 위험 선호를 분리해 기록한다.

## 18. 첫 구역 UX와 선택의 체감 설계 v0.9

2026-11-06 한국. 기존 경제·해금·원정 규칙은 유지한다. 이번 절은 기본 청소의 화면·조작·피드백을 제작 가능한 수준으로 명시한다. 아래 시간·크기는 초기 제작값이며 실제 기기에서 검증된 값은 아니다.

### 18.1 첫 화면에서 보여줄 것

첫 실행은 짧은 시작 화면에서 ‘청소 시작’과 설정만 제공한다. 한 번 누르면 착륙장에 들어간다. 원정·도감·기지·구매 메뉴를 첫 실행의 필수 단계로 만들지 않는다. 저장이 있으면 ‘이어하기’를 기본 행동으로 제공하고 새 시작은 별도 확인을 거친다.

세로 화면의 필수 정보 우선순위:

| 영역 | 표시 | 설계 규칙 |
|---|---|---|
| 상단 첫 줄 | 착륙장·일시정지 | 구역 이름은 줄일 수 있지만 일시정지는 유지 |
| 상단 둘째 줄 | 청소 진행률·적재량 | 숫자와 막대 병기, 색만으로 상태 구분하지 않음 |
| 현장 | 플레이어·먼지·회수소 방향 | 최초 진입에서 회수소와 첫 군집이 함께 보임 |
| 하단 좌측 | 이동 패드 | 오른손 배치 선택 시 좌우 교환 |
| 하단 우측 | 회수소로·도구 | 원정의 ‘탐사 종료’와 다른 이름 사용 |
| 회수소 근처 | 판매·장비 개선 | 현장 어디서나 긴 구매 목록을 띄우지 않음 |

360 CSS px 폭을 기준으로 좌우 바깥 여백12, 주요 버튼 높이48 이상, 버튼 사이8 이상을 제작 기준으로 둔다. 안전 영역은 별도로 확보한다. 기기 높이가 작으면 상단 구역명과 상세 통계를 접고 핵심 버튼과 적재량을 남긴다. 가로 회전 때는 일시정지 후 재배치하고 사용자가 재개한다. 세로 방향으로 기기를 돌리라고 강제 차단하지 않는다.

수치는 터치 목표의 제작 기준이다. 문구 확대·브라우저 확대·주소창 높이 변화·화면 잘림까지 검증해야 모바일 대응 완료로 판정한다.

### 18.2 조작 상태와 입력 우선순위

이동 입력은 게임 화면의 지정 패드 영역에서 시작한 터치만 받는다. 버튼에서 시작한 터치를 이동으로 해석하지 않는다. 이동 중 다른 손으로 메뉴를 열면 이동과 청소를 멈춘다. 메뉴를 닫아도 이전 터치 방향을 자동 복원하지 않으며 새 이동 입력을 기다린다.

일반 청소는 정지해도 마지막 방향의 범위 안 먼지를 수집한다. 메뉴·일시정지·백그라운드에서는 멈춘다. 적재량이 가득 차면 청소만 정지하고 이동은 유지한다. 벽을 통과해 먼지를 수집하지 않도록 도구와 대상 사이의 차단 여부를 확인한다.

여러 먼지 타일이 범위에 들어오면 도구의 총 처리율 예산을 나눠 쓴다. 작은 잔여물이 많은 타일을 먼저 마무리하는 규칙을 초기안으로 두어 청소된 바닥이 자주 드러나게 한다. 같은 진행량에서는 거리, 그다음 고정 타일 ID 순으로 결정한다. 새 먼지를 임의로 생성하거나 처리율을 초과해서 빠르게 보이게 하지 않는다.

‘회수소로’는 안전한 경로를 따라 자동 이동한다. 새 이동 입력·도구 메뉴·일시정지가 들어오면 자동 이동을 취소한다. 길을 찾지 못하면 계속 벽에 밀지 않고 정지해 회수소 방향을 표시한다. 회수소 도착 후 판매는 별도 버튼 한 번으로 확정한다. 기존 드론의 자동 판매와 구분한다.

### 18.3 행동마다 결과를 알아볼 수 있게 하기

| 행동 | 화면 반응 | 소리·진동 | 결과의 정확성 |
|---|---|---|---|
| 먼지 수집 시작 | 도구 범위와 먼지 감소 | 낮은 지속 작업음 | 실제 작업이 있을 때만 반응 |
| 타일 청소 완료 | 바닥 무늬 노출, 짧은 먼지 흡입 | 작은 완료음 | 완료 타일을 다시 더럽히지 않음 |
| 적재80% | 적재 막대 강조 | 기본은 무음 | 드론 해금 전 과도한 안내 금지 |
| 만재 | ‘적재함이 가득 찼어요’ | 설정 시 짧은 진동1회 | 이동 가능·청소 정지 구분 |
| 판매 | 판매량과 실제 증가 크레딧 | 짧은 정산음 | 저장 성공 후 지갑 증가 표시 |
| 업그레이드 | 이전→새 처리율 비교 | 짧은 기계음 | 처리율 변화가 실제 작업에 반영 |
| 구역 완료 | 청소된 전경과 정산 | 짧은 완료음 | 지급 완료 뒤 화면 표시 |

수집 숫자는 먼지 한 단위마다 띄우지 않고 짧은 구간의 합으로 묶는다. 파티클·흔들림·진동을 끈 상태에서도 적재량·바닥 변화·진행률로 행동 결과를 이해할 수 있어야 한다. 중요 안내는 소리만으로 전달하지 않는다.

완료 연출은 목표0.8초 안팎으로 제작하되 건너뛰기를 허용한다. 파티클의 생성 수와 화면상 총수를 제한하고, 성능이 부족하면 시각 효과를 줄인다. 저사양 기기에서 경제·작업 속도가 함께 느려지는 것을 연출 설정으로 덮지 않는다.

### 18.4 첫 구역의 구매 경험

첫 판매90크레딧에서 처리율1단계50을 구매하면40이 남는다. 구매 화면은 ‘일반 먼지6→7.2/초’, ‘가격50’, ‘구매 후40’을 한 화면에 보여준다. 처리율 개선을 사지 않아도 구역을 끝낼 수 있다. 구매를 닫았다고 안내를 반복 팝업으로 띄우지 않는다.

비교용 단순 모델:900먼지, 적재90, 판매10회, 마지막을 제외한 왕복9회 각8초, 마지막 편도4초, 판매 처리 대기0초로 가정한다. 강화가 없으면 순수 작업150+이동76=226초다. 첫90을 모은 뒤 강화하면 작업15+810/7.2=127.5초, 이동 포함203.5초다. 모델상 약22.5초 줄어든다.

이는 업그레이드 메뉴에서 고민하는 시간, 타일 간 이동, 범위 밖 공회전을 포함하지 않는다. 공간 배치에 따라 이동과 작업이 겹칠 수도 있어 실제 완주 시간을 예측하는 값이 아니다. 사용자에게 ‘22.5초 빨라짐’이라고 보장하지 않고 실제 처리율만 표시한다.

성장의 체감은 구매 직후 다시 먼지에 접근했을 때 확인한다. 수치를 크게 띄우는 연출보다 같은 바닥이 더 빨리 드러나는지가 중요하다. 체감이 없으면 가격·배율만 높이기 전에 첫 작업 구간의 먼지 밀도와 도구 범위를 점검한다.

### 18.5 모듈의 큰 숫자가 실제 이득인지 확인

3구역은 일반900·고밀도300, 처리율1단계×1.2다. 일반에 광폭, 고밀도에 집중 도구를 사용하는 모델에서는900/8.4+300/7.2≈148.81초가 걸린다.

압축 분쇄의 고밀도+50%·일반−10%를 적용하면900/7.56+300/10.8≈146.83초다. 순수 작업 시간 감소는 약1.98초,1.33%뿐이다. 도구 교체·이동은 제외했다. 따라서 ‘+50%’를 전체 성능 개선처럼 강조하면 잘못된 기대를 만들 수 있다.

| 모듈 | 실제 선택 이유 | 카드에 함께 표시할 손해·조건 | 첫 관찰 포인트 |
|---|---|---|---|
| 광폭 헤드 | 흩어진 먼지를 범위에 넣기 쉬움 | 이동−10%, 총 처리율 증가 아님 | 헛이동·빈 범위 작업이 줄어드는가 |
| 압축 분쇄 | 고밀도 군집을 먼저 빨리 처리 | 일반 처리율−10% | 해당 군집에서는 차이를 느끼는가 |
| 귀환 터빈 | 만재에 가까울 때 왕복 단축 | 적재80% 미만에서는 효과 없음 | 발동 조건을 이해하는가 |
| 자성 연결 | 연결 군집에 진행 전달 | 추가 연쇄 없음 | 밀집 군집을 찾아 이동하는가 |
| 탐지 렌즈 | 미발견 유물을 찾기 쉬움 | 청소 속도·판매액 변화 없음 | 발견물을 놓칠 걱정이 줄어드는가 |
| 정밀 분류 | 같은 먼지에서 판매액 증가 | 처리율−10% | 보상 증가와 소요 시간 교환을 이해하는가 |

정밀 분류는 순수 작업 시간만 보면 처리율0.9×판매액1.1=0.99이므로 분당 판매액이 자동으로 증가하지 않는다. 이동 시간이 포함되면 결과는 달라진다. ‘돈을 더 받음’과 ‘시간당 돈을 더 벌음’을 구분한다.

현재 수치는 유지하며 카드 설명과 체감 검증을 먼저 한다. 압축 분쇄를 선택한 사용자가 이득을 전혀 느끼지 못하면 일반 페널티 축소 또는 고밀도 비중 조정을 한 번에 하나씩 비교한다. 모든 모듈을 총 처리율 증가로 바꾸지 않는다.

### 18.6 끝내고 나가는 경험

정산에는 먼지 판매 누계, 모듈 추가액, 최초 완료 보상, 이미 소비한 업그레이드 비용을 구분한다. 이번에 새로 지급하는 최초 보상과 이전 판매 누계를 합쳐 전부 새로 받은 것처럼 표시하지 않는다.

다음 구역의 새 경험은 한 문장으로 소개한다. 예: ‘화물 통로에서는 넓은 브러시로 흩어진 먼지를 모아보세요.’ ‘다음 구역’과 ‘거점으로’ 버튼을 함께 둔다. 자동 카운트다운 출발은 없다. 첫 구역만 제공하는 프로토타입은 ‘다음 구역 준비 중’ 대신 ‘테스트 완료’로 끝내고 구현되지 않은 플레이로 연결하지 않는다.

완료한 착륙장 감상은 무료다. 연습 청소는 별도 사본이고 경제 보상이 없음을 시작 전에 표시한다. 진척을 지우지 않아도 재연습할 수 있게 한다.

### 18.7 기본 청소 UX 수용 사례

| 상황 | 기대 동작 |
|---|---|
| 손가락이 패드 밖으로 나감 | 시작한 입력은 추적하되 화면을 벗어나 취소되면 이동 정지 |
| 작업 중 메뉴 열기·닫기 | 열 때 정지, 닫은 뒤 이전 이동 입력 자동 재개 없음 |
| 만재 상태에서 먼지 위 이동 | 위치만 변경, 먼지량·적재량은 유지 |
| 자동 귀환 중 직접 방향 입력 | 자동 경로 즉시 취소 |
| 모서리 너머 먼지 존재 | 벽을 가로질러 청소되지 않음 |
| 효과·소리·진동 모두 끔 | 만재·판매·완료 상태를 읽을 수 있음 |
| 회전·백그라운드 복귀 | 재배치·복원 후 사용자 재개, 자동 이동 없음 |
| 최초 판매 후 업그레이드 구매 | 지갑90→40, 처리율6→7.2, 중복 구매 방지 |
| 첫 구역 재정산 | 최초 보상100은 다시 지급되지 않음 |
| 압축 분쇄 카드 열람 | 고밀도+50%와 일반−10%가 동시에 보임 |

이번에 실행한 것은 첫 구역 시간 모델과3구역 모듈 효용의 산술 계산이다. 화면 렌더링·접근성·실기기 성능·플레이 테스트는 아직 실행하지 않았다. 다음 구현에서는 A단계 첫 구역과 이 절의 상태·피드백을 우선 적용하고, 원정 보너스는 기본 조작을 검증한 뒤 진행한다.

## 19. 첫 구현 기준 통합 v1.0

2026-11-08 한국. v1.0은 설계 기준의 버전이며 게임1.0 출시를 의미하지 않는다. 이 절은 착륙장 A단계의 빠진 수치와 충돌 규칙을 정리한다. 미기재 항목은 아래 참조표에 따른다. 연구·실험안은 기본 플레이에 자동 편입하지 않는다.

### 19.2 착륙장 지도 확정안

24×32타일, 좌상단(0,0), 오른쪽+x, 아래+y다. 좌표의 정수는 타일 인덱스이며 타일 중심은(x+0.5,y+0.5)다. 경계 밖은 이동 불가다. 첫 구역 내부에는 이동을 막는 장애물을 배치하지 않는다. 장식은 충돌·채굴 대상이 아니다.

| 내용 | 타일 범위 또는 중심 | 수량 |
|---|---|---:|
| 왼쪽 상단 군집 | x6~11, y8~12, 양끝 포함 | 30타일×10먼지=300 |
| 오른쪽 상단 군집 | x14~19, y8~12, 양끝 포함 | 30타일×10먼지=300 |
| 첫 작업 군집 | x9~14, y17~21, 양끝 포함 | 30타일×10먼지=300 |
| 회수소 | 중심(12.5,26.5), 작동 반경1.5 | 먼지 없음 |
| 시작 위치 | 중심(12.5,25.5), 위쪽 바라봄 | 먼지 없음 |

총90타일·900먼지다. 세 군집은 겹치지 않는다. 시작 주변3×3은 비어 있고 가장 가까운 군집은 위쪽에 있다. 기존 U자형 표현은 이 세 군집 배치로 구체화하며, 시각적 장식을 위해 총량이나 접근성을 바꾸지 않는다.

지도 전체를 화면에 축소하지 않는다. 카메라는 플레이어를 따라가며 가장자리에서는 지도 바깥을 드러내지 않도록 제한한다. 첫 화면에 회수소와 가까운 먼지가 함께 보이도록 세로 가시 범위는 최소10타일을 목표로 한다. 타일 표시 크기는 화면과 UI 공간에 따라 조정하되 논리적 처리율은 변하지 않는다.

### 19.3 플레이어와 도구의 실제 크기

| 항목 | 초기 제작값 | 적용 |
|---|---:|---|
| 이동 속도 | 2타일/초 | 캠페인 이동 강화 배수는 이후 적용 |
| 플레이어 충돌 반경 | 0.3타일 | 경계와 장애물의 판정에 사용 |
| 기본 도구 작업 길이 | 전방1.8타일 | 플레이어 중심에서 앞쪽으로만 적용 |
| 기본 도구 작업 폭 | 1.4타일 | 진행 방향을 중심으로 좌우0.7 |
| 광폭 상대 폭 | ×1.6 | 2.24타일, 길이는 동일 |
| 집중 상대 폭 | ×0.8 | 1.12타일, 길이는 동일 |
| 판매 거리 | 회수소 중심1.5타일 이내 | 버튼 활성 조건 |

도구 방향은 마지막 유효 이동 방향을 따른다. 회전 중 범위도 실제 방향으로 회전하고, 타일 중심이 작업 직사각형 안에 있을 때 해당 타일을 대상으로 삼는다. 범위 끝에 닿기만 한 타일의 처리 여부가 프레임마다 바뀌지 않도록 동일한 포함 규칙을 쓴다. 사선 이동 속도는 가로·세로보다 빨라지지 않는다.

광폭 도구의 넓이는 접근·정렬을 쉽게 하는 효과이며 범위 안 타일 수에 비례해 초당 처리량을 늘리지 않는다. 첫 A단계는 기본 도구만 사용한다. 광폭·집중 수치는 다음 단계의 참조값이다.

### 19.4 작업량과 정수 자원의 경계

한 작업 단계에서는 남은 먼지가 적은 타일부터 처리한다. 타일에 작업을 배분할 때 ‘초’를 예산으로 사용한다. 예를 들어 기본 도구로 일반 먼지1을 회수하면1/6초, 고밀도1은1/3초를 쓴다. 종류가 다른 타일을 동시에 잡았다고 각각 전체 처리율을 주지 않는다. 이번 단계의 시간이 남으면 다음 타일에 사용하고 대상이 없으면 남은 작업 시간을 저장해 두지 않는다.

부분 작업은 아직 회수되지 않은 다음 먼지1개의 진행률로 저장한다. 정수1개가 완료되는 순간 타일 잔여량−1과 적재량+1을 함께 반영한다. 부분 작업 중에는 정수 잔여량을 줄이지 않는다. 같은 구역에서 대상 변경·도구 교체·일시중단으로 부분 진행을 지우지 않는다. 도구 교체 뒤에는 남은 진행량에 새 처리율을 적용한다.

예: 일반 먼지를 기본 처리율6으로0.25초 작업하면1개 회수, 다음1개50% 진행이다. 남은 부분을7.2/초 도구로 처리하는 데는0.5/7.2초가 필요하다. 이 진행률은 별도 재화가 아니므로 자원 보존 합계에 더하지 않는다.

적재89/90에서 먼지1개를 완료하면90이 되는 순간 멈춘다. 남은 시간 예산으로 타일을 더 줄이지 않는다. 만재 중 작업음·흡입 효과도 멈추며 이동은 가능하다. 판매 후 다시 작업할 때 완료된 먼지가 중복 처리되지 않아야 한다.

### 19.5 첫 구역 판매·구매·완료의 숫자 예시

| 순서 | 상태 변화 | 확인할 값 |
|---|---|---|
| 처음90 회수 | 잔여810·적재90 | 판매 전 지갑0 |
| 첫 판매 | 적재0·누적판매90 | 지갑90 |
| 처리율 구매 | 비용50, 6→7.2/초 | 지갑40 |
| 나머지810 판매 | 누적판매900 | 지갑850 |
| 최초 완주 | 보상100을 한 번 지급 | 지갑950 |
| 정산 다시 열기 | 영수증만 표시 | 지갑950 유지 |

강화를 사지 않았다면 최초 완료 후 지갑은1000이다. 강화 구매가 최초 완료 조건은 아니다. 일반 구역 정산의 ‘판매900’은 이미 받은 수입의 내역이며 최초 보상100과 함께1000을 새로 지급하는 의미가 아니다.

95%는45먼지 이하, 마무리 회수 기준99.5%는정수 잔여4 이하일 때다. 잔여5는895/900≈99.444%이므로 대상이 아니다. 표시 진행률을 반올림해99.5%라고 보이더라도 반올림값으로 조건을 판정하지 않는다. UI는 대상이 아니면 ‘마무리 회수’ 버튼을 활성화하지 않는다.

청소가 끝나도 적재가 남으면 회수소로 안내한다. 회수소에서 마무리를 확정하면 남은 바닥 먼지·적재·최초 보상을 하나의 정산으로 처리한다. 최초 완료 이후 재방문은 추가 최초 보상이 없으며, 연습은 별도 사본으로 시작한다.

### 19.6 저장·오류 화면의 사용자 행동

시작·이어하기·일시정지·정산에서 저장 상태를 작은 문구로 표시한다. 실패 시 ‘저장되지 않았어요. 다시 시도하거나 저장 파일을 내려받으세요’와 두 행동을 제공한다. 실패한 구매·판매를 성공처럼 표시하지 않는다.

정상 저장을 읽을 수 없으면 자동으로 새 게임을 덮어쓰지 않는다. 이전 정상 저장 복구, 원본 저장 내려받기, 명시적인 새 시작을 구분한다. 내보내기가 해당 환경에서 불가능하면 가능한 복구 동작만 표시하고 성공했다고 말하지 않는다.

첫 공개판에서 여러 탭이 동시에 열려 있으면 하나만 플레이하고 나머지는 읽기 상태로 안내한다. 진행 중 버전을 업데이트할 때는 현장 작업을 저장한 뒤 재시작하도록 한다. 저장 형식이 호환되지 않는 경우에는 이전 저장을 보존하고 변경 내용을 안내한다.

### 19.7 첫 실행판의 제작 완료 기준

제작 완료와 게임 재미 검증은 구분한다. 첫 실행판의 최소 완료 조건은 다음과 같다.

- 모바일 터치와 데스크톱 방향키/WASD로 같은 화면 방향으로 이동한다.
- 900먼지가 중복·소실 없이 수집·판매되고, 50크레딧 구매와100 최초 보상이 한 번씩 반영된다.
- 정지·만재·메뉴·백그라운드의 작업 정지 규칙이 일치한다.
- 저장 후 새로고침으로 위치·적재·지갑·잔여 먼지·부분 작업이 함께 복원된다.
- 360px 폭에서 버튼이 겹치지 않고, 완주 뒤 구현되지 않은 구역으로 이동하지 않는다.

이 목록을 실행하기 전에는 ‘첫 실행판 완료’로 표시하지 않는다. 구현 뒤17절의 실제 사용자 검증으로 진행한다. 다음 설계 변경은 조작·시간·재미의 측정 결과를 근거로 한다.
